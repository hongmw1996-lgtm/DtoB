# PHASE03G QA fixture manifest

`manifest.json` inventories all86 reviewed disk DXF/byte fixtures: official controlled1,
03B20,03C16,03D12,03E18,03F2,03G17. Paths are repository-relative; entries sort
ordinally. Expected statuses/codes come from hand-reviewed bytes, previous fixture
READMEs and earlier assertions, not a production-output generator. Diagnostic code
lists identify mandatory codes, not necessarily every emitted informational code.
`ExpectedStage` is the acceptance boundary being tested; earlier fixtures do not
implicitly promise complete03E/03F acceptance. Exact value expectations are also
in owning tests and folder READMEs.

The17 `.bin` files deliberately contain byte sequences inappropriate for normal
UTF-8 source editing. They include valid multilingual and BOM/line-ending controls
as well as invalid encoding/signature/group-code cases. Recreate deterministically:

```powershell
./scripts/qa/New-Phase03GFixtures.ps1
```

This QA-only script overwrites only these named generated byte fixtures and the
manifest; it hashes existing DXFs without writing them. No project schema or
production dependency is introduced. Positive signed group codes (`+1`) are
accepted by the existing03A numeric profile; negative/out-of-range codes refuse.
Do not infer a new sign restriction from the corruption campaign wording.

Additional named actual Text DXF cases are constructed in
`ExtractionQaCampaignTests.Adversarial.cs` and the limit/cancellation harnesses.
Their stable case IDs/source strings are checked-in test data; execution exports
the corruption sources to ignored evidence. They are not CAD application exports,
an exhaustive fuzz corpus, legacy ANSI decoding evidence or DWG equivalence claims.

Coverage and limits: `docs/status/PHASE_03G_COVERAGE.md`,
`PHASE_03G_LIMIT_MATRIX.md`, `PHASE_03G_CANCELLATION_MATRIX.md`.
